# Firebase Setup for Calcula UAT

This document describes how to configure a Firebase project for Calcula UAT v2.0.0.

Calcula UAT consists of two client applications that share the same Cloud Firestore database:

- the Next.js/React web application;
- the Flutter/Android mobile application.

For reproducibility, developers should use their own Firebase project rather than depend on the Firebase project used during the original research deployment.

---

## 1. Create a Firebase project

Create a new project in the Firebase Console:

https://console.firebase.google.com/

The Firebase project name and project identifier can be selected by the developer.

The original research deployment used a project named:

```text
academic-platform
```

A new installation does not need to use the same project identifier.

---

## 2. Enable Cloud Firestore

Inside the Firebase project:

1. Open **Build → Firestore Database**.
2. Create a Cloud Firestore database.
3. Select an appropriate Firebase region.
4. Configure security rules appropriate for the intended deployment.

Calcula UAT requires the following principal collections:

```text
institutions
categories
problems
responses
```

Their structure is documented in:

```text
docs/DATA_MODEL.md
```

The collections do not need to be created manually before first use. Cloud Firestore creates collections when documents are first written.

---

## 3. Register the web application

In Firebase:

1. Open **Project settings → General**.
2. Select **Add app → Web**.
3. Register a web application.
4. Copy the Firebase configuration generated by Firebase.

The configuration has the following structure:

```javascript
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```
In the Calcula UAT web repository, Firebase configuration is provided through environment variables.

A configuration template is available at:

```text
.env.example
```

For local execution, create a file named:

```text
.env.local
```

based on `.env.example`.

Populate the following variables with the values generated by your Firebase project:

```text
NEXT_PUBLIC_FIREBASE_API_KEY
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
NEXT_PUBLIC_FIREBASE_PROJECT_ID
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
NEXT_PUBLIC_FIREBASE_APP_ID
```

The application reads these variables in:

```text
src/services/firebase.js
```

Do not commit `.env.local` to the public repository.

Do not modify the Firestore helper functions unless the application architecture is intentionally being changed.


---

## 4. Register the Android application

In the same Firebase project:

1. Open **Project settings → General**.
2. Select **Add app → Android**.
3. Use the following Android package name:

```text
uat.uamm.calculauat
```

4. Complete the Firebase registration.
5. Download the generated file:

```text
google-services.json
```

Place it at:

```text
android/app/google-services.json
```

The `package_name` inside the Firebase-generated file must correspond to:

```text
uat.uamm.calculauat
```

The file should be generated by Firebase rather than manually edited.

---

## 5. Configure Firebase in the Flutter application

The Flutter application initializes Firebase using:

```text
lib/firebase_options.dart
```

For a new Firebase project, the recommended approach is to regenerate this file using the FlutterFire CLI.

A typical local development workflow is:

```bash
dart pub global activate flutterfire_cli
```

Then, from the root directory of the mobile project:

```bash
flutterfire configure
```

Select the Firebase project created for the Calcula UAT installation and configure the Android application:

```text
uat.uamm.calculauat
```

The command generates or updates:

```text
lib/firebase_options.dart
```

After configuration, the Android Firebase options must correspond to the same Firebase project used by the web application.

---

## 6. Verify the shared Firebase project

Both Calcula UAT components must communicate with the same Cloud Firestore database.

Verify that the following values correspond to the same Firebase project:

### Web

```text
academic-web-app-v2/src/services/firebase.js
```

### Mobile

```text
academic-mobile-app/lib/firebase_options.dart
```

and:

```text
academic-mobile-app/android/app/google-services.json
```

The `projectId` should identify the same Firebase project in both applications.

## 7. Populate initial data

The system requires at least one institutional record before the complete workflow can be tested.

An example development record is:

```json
{
  "scholarKey": "DEMO01",
  "email": "demo@example.edu",
  "institutionName": "Demo Institution",
  "password": "demo-password",
  "academicLevel": [
    "college",
    "high",
    null,
    null
  ]
}
```

This example is intended only for a local or isolated demonstration database.

Do not use example passwords or sensitive personal information in a public or production database.

After an institution is available, categories and mathematical problems can be created through the Calcula UAT web interface.

---

## 8. Data flow

The expected data flow is:

```text
Web application
      |
      | creates
      v
categories / problems
      |
      | retrieved from Firestore
      v
Android application
      |
      | records completed interactions
      v
responses
      |
      | retrieved from Firestore
      v
Web analytics interface
```

Both clients communicate directly with Cloud Firestore through the corresponding Firebase SDKs.

The current implementation does not require a dedicated custom REST API or separate application server.

---

## 9. Offline persistence

The Android application explicitly enables Cloud Firestore local persistence.

This allows previously retrieved content to remain available during intermittent connectivity and allows Firestore writes to be queued locally until connectivity is restored.

Offline functionality has an important limitation:

```text
Educational content that has never been retrieved by the device cannot be loaded from the Firestore cache while the device is offline.
```

The current architecture should therefore be described as supporting intermittent connectivity rather than guaranteeing unrestricted offline operation.

---

## 10. Security considerations

Calcula UAT v2.0.0 is a research prototype.

The current institutional access mechanism stores institutional access information in Firestore and does not constitute a production-grade identity-management system.

For this reason:

- use a separate Firebase project for reproduction or demonstration;
- do not populate a public test database with sensitive information;
- do not reuse real institutional passwords;
- apply appropriate Firestore security rules;
- use managed authentication before production-scale deployment.

The repository does not claim that the current prototype authentication model is suitable for production use.

Future versions should migrate institutional authentication to a managed identity service such as Firebase Authentication and implement more granular authorization policies.

---

## 11. Firebase configuration identifiers

Firebase configuration values such as `apiKey`, `appId`, `projectId`, and `messagingSenderId` identify a Firebase application and project.

Access to Firestore data must not rely on the secrecy of these identifiers. Database protection should be implemented through authentication, authorization, and Firestore security rules.

---

## 12. Verification checklist

Before running Calcula UAT, verify:

- [ ] Cloud Firestore is enabled.
- [ ] The web application is registered in Firebase.
- [ ] The Android application is registered with package name `uat.uamm.calculauat`.
- [ ] `src/services/firebase.js` contains the configuration for the selected Firebase project.
- [ ] `lib/firebase_options.dart` contains the configuration for the same Firebase project.
- [ ] `android/app/google-services.json` belongs to the same Firebase project.
- [ ] The required institutional test data are available.
- [ ] No sensitive production credentials are being used for testing.
- [ ] Firestore access rules are appropriate for the intended environment.
